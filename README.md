# tp92 检查规则与命中清单工作台

一个本地小工具：把团队约定要检查的写法整理成规则，把需要检查的文件内容收进来，点一下扫一遍，命中的地方会记到具体的文件与行上。规则编码写得不合规矩、同一条规则编码重复使用、文件路径重复收录、内容为空，保存时当场就会指出来。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5092>

端口固定为 `5092`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 规则区列出编码、名称、级别、状态、适用文件类型与匹配写法，可以按级别、状态、适用文件类型筛选，也能按编码、名称或匹配写法搜索；支持新建、编辑与删除
2. 文件区列出收录进来的文件路径、类型、行数与更新时间，点看内容可以把整份内容展开在下面；点编辑会把路径、内容与备注回填到表单，支持收录新文件与移出清单
3. 命中清单区扫之前先挑这一轮的范围，几项可以叠加：填一个目录前缀（路径等于该目录或落在它下面才算覆盖到，留空扫全部）、选一种文件类型、在规则清单里勾若干条具体规则（不勾等于全部启用规则，停用规则会标灰并提示不参与）、按级别勾选；还能给命中条数设上限（留空不限制）
4. 范围一边改，扫的按钮旁边一边写明这一轮将使用几条规则、覆盖几个文件；范围一个文件都覆盖不到、或一条规则都没选中时，这里先给出说明，点扫也会被拦下，不会给一份空清单
5. 点按选定范围扫一遍后，页面给出参与比对的规则条数、覆盖文件个数、一共命中多少条，并按级别、按规则、按文件分别汇总；命中超过上限时，清单只保留按规则编码、路径、行号排序后的前若干条，并明确写出一共命中多少、截掉多少
6. 命中条数上限只能填大于 0 的整数，填 0、负数、小数或非整数文本会当场拒绝，并把问题标到上限输入项上
7. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上

## 比对口径

- 只有状态为启用的规则参与比对，停用的规则不会产生命中；勾选的规则里混有停用规则时，页面上会写明这几条没有参与
- 适用文件类型写成全部的规则管所有文件，写成某一种类型的只比对该类型的文件，类型按路径后缀判断（支持 js、sh、md、yml）
- 目录前缀按路径段匹配：`src/server` 覆盖 `src/server/api.js`，但不覆盖 `src/server-extra/x.js`；结尾的斜线会被忽略
- 目录前缀、文件类型、勾选的规则与级别之间是叠加关系，逐项收窄
- 一条规则命中与否看文件里有没有出现它登记的匹配写法，区分大小写，命中的是包含这个写法的整行
- 命中按规则编码、文件路径、行号排序，同一行同时踩到多条规则时逐条各记一条
- 设了命中条数上限且命中总数超过它时，清单只保留排序后的前 N 条；按级别、按规则、按文件的汇总与"一共命中"数始终按全部命中统计，不受截断影响

## 登记口径

- 规则编码写成大写字母加短横线加数字，例如 `CODE-001`，最长 20 个字符，且不能重复
- 级别只有三种：提示、警告、错误
- 状态只有两种：启用、停用
- 匹配写法不能为空，最长 60 个字符
- 文件路径最长 120 个字符，只用字母数字、点、下划线、短横线与斜线，后缀必须是收录范围内的几种，且不能重复
- 文件内容不能为空，最长 4000 个字符

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "rules": [...], "files": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

## 接口一览

| 方法   | 路径              | 说明                                             |
| ------ | ----------------- | ------------------------------------------------ |
| GET    | /api/health       | 服务状态检查                                     |
| GET    | /api/rules        | 规则清单，支持按级别、状态、适用文件类型筛选与关键词搜索 |
| POST   | /api/rules        | 新建规则                                         |
| GET    | /api/rules/:id    | 查看单条规则                                     |
| PATCH  | /api/rules/:id    | 修改规则                                         |
| DELETE | /api/rules/:id    | 删除规则                                         |
| GET    | /api/files        | 文件清单，支持按类型筛选与关键词搜索             |
| POST   | /api/files        | 收录文件                                         |
| GET    | /api/files/:id    | 查看单个文件（含完整内容）                       |
| PATCH  | /api/files/:id    | 修改文件                                         |
| DELETE | /api/files/:id    | 把文件移出清单                                   |
| POST   | /api/scan         | 按选定范围（目录前缀、文件类型、规则编号列表、级别列表、命中上限）扫一遍，返回命中清单、截断信息与汇总 |

`POST /api/scan` 的请求体字段都可省略：`dirPrefix`（目录前缀字符串）、`fileType`（js/sh/md/yml 之一）、`ruleIds`（规则 id 的数组，空数组等于全部启用规则）、`levels`（提示/警告/错误 的数组）、`limit`（大于 0 的整数，或留空/不传表示不限制；0、负数、小数与非整数文本返回 `LIMIT_INVALID`）。范围挑空时不报错，返回里 `notice` 写明原因、`hits` 为空；发生截断时 `summary.truncated` 为真，并带 `summary.total`（全部命中数）、`summary.returned`（清单条数）、`summary.omitted`（截掉条数）与 `summary.limit`。

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
