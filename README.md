# tp92 检查规则与命中清单工作台

一个本地小工具：把团队约定要检查的写法整理成规则，把需要检查的文件内容收进来，点一下扫一遍，命中的地方会记到具体的文件与行上。规则编码写得不合规矩、同一条规则编码重复使用、文件路径重复收录、内容为空，保存时当场就会指出来。

数据全部存在本机的数据文件里，不连数据库，也不调用任何外部服务。

## 技术栈

- 后端：Node.js（>=18）与 Express，前后端同一个进程
- 前端：原生 HTML、CSS 与 JavaScript，页面文件由后端静态目录直接提供，没有构建步骤
- 存储：本地 JSON 文件 `data/db.json`

## 启动方式

```bash
npm install
npm start
```

启动后打开页面地址：<http://localhost:5092>

端口固定为 `5092`，如需临时改动可在启动前设置环境变量 `PORT`。

## 页面怎么用

1. 规则区列出编码、名称、级别、状态、适用文件类型与匹配写法，可以按级别、状态、适用文件类型筛选，也能按编码、名称或匹配写法搜索；支持新建、编辑与删除
2. 文件区列出收录进来的文件路径、类型、行数与更新时间，点看内容可以把整份内容展开在下面；点编辑会把路径、内容与备注回填到表单，支持收录新文件与移出清单
3. 命中清单区顶部可以把几项范围叠加着选：填一个目录前缀（只看这个目录下的文件）、选一种文件类型、勾选具体的几条规则、勾选一个或几个级别；任何一项留空或不勾都表示不做这方面的限制。点按范围扫一遍之前，范围区会先写明这一轮会用到几条规则、覆盖几个文件；勾了停用规则或被级别挡掉的规则时，也会写明有几条不参与
4. 命中条数可以设上限：超过上限时清单里只保留排序后的前若干条，并明确写出已截断、一共命中多少条、截掉多少条；上限填 0、负数、小数或其他文字会当场拒绝。范围一个文件都不覆盖、参与规则一条都没有时，不会给一份空清单，而是直接说明原因
5. 任何一步不成立时，页面顶部给出说明，并尽量把问题标到对应的输入项上

## 比对口径

- 只有状态为启用的规则参与比对，停用的规则不会产生命中；勾选了停用规则或被级别筛选挡掉的规则时，结果上方会逐条写明它这一轮没有参与
- 扫描范围由四项叠加缩小：目录前缀（相对路径，文件路径等于前缀或在前缀的下一级目录下才算覆盖）、文件类型、勾选的具体规则、勾选的级别；四项都不填不勾就是全量扫描
- 适用文件类型写成全部的规则管所有文件，写成某一种类型的只比对该类型的文件，类型按路径后缀判断（支持 js、sh、md、yml）
- 一条规则命中与否看文件里有没有出现它登记的匹配写法，区分大小写，命中的是包含这个写法的整行
- 命中按规则编码、文件路径、行号排序，同一行同时踩到多条规则时逐条各记一条
- 命中条数上限留空表示不限；填了正整数时清单只保留排序后的前若干条，汇总仍按全部命中统计，并通过 `truncated`、`totalHits`、`truncatedCount` 标明截断情况；0、负数、小数或非整数一律拒绝
- 范围一个文件都不覆盖、参与规则一条都没有时不出空清单，返回 `emptyReason` 说明原因（页面上显示同样的说明）

## 登记口径

- 规则编码写成大写字母加短横线加数字，例如 `CODE-001`，最长 20 个字符，且不能重复
- 级别只有三种：提示、警告、错误
- 状态只有两种：启用、停用
- 匹配写法不能为空，最长 60 个字符
- 文件路径最长 120 个字符，只用字母数字、点、下划线、短横线与斜线，后缀必须是收录范围内的几种，且不能重复
- 文件内容不能为空，最长 4000 个字符

## 数据存储

所有数据写在 `data/db.json`，结构为 `{ "rules": [...], "files": [...] }`。落盘时先把内容写进同名临时文件，再用改名的方式替换正式文件，写入过程中断也不会把数据文件写坏；文件缺失或内容损坏时会自动回落到初始数据。

## 接口一览

| 方法   | 路径              | 说明                                             |
| ------ | ----------------- | ------------------------------------------------ |
| GET    | /api/health       | 服务状态检查                                     |
| GET    | /api/rules        | 规则清单，支持按级别、状态、适用文件类型筛选与关键词搜索 |
| POST   | /api/rules        | 新建规则                                         |
| GET    | /api/rules/:id    | 查看单条规则                                     |
| PATCH  | /api/rules/:id    | 修改规则                                         |
| DELETE | /api/rules/:id    | 删除规则                                         |
| GET    | /api/files        | 文件清单，支持按类型筛选与关键词搜索             |
| POST   | /api/files        | 收录文件                                         |
| GET    | /api/files/:id    | 查看单个文件（含完整内容）                       |
| PATCH  | /api/files/:id    | 修改文件                                         |
| DELETE | /api/files/:id    | 把文件移出清单                                   |
| POST   | /api/scan         | 按启用的规则扫一遍，返回命中清单与汇总；请求体支持 `dirPrefix`（目录前缀）、`fileType`、`ruleIds`（规则 id 数组，也兼容单个 `ruleId`）、`levels`（级别数组，也兼容单个 `level`）、`limit`（正整数或留空），范围参数叠加生效 |

接口出错时统一返回 `{ "error": { "code": "...", "message": "...", "field": "..." } }`，其中 `field` 用于让页面把问题标到具体的输入项上。
